1. SYSTEM CONTEXT (FROM DOCUMENTATION - DO NOT CHANGE CONCEPT)
--------------------------------------------------------------------------------
- Three-tier client-server: Client (React PWA web app, browser, mobile + low-bandwidth
  optimized) -> Server (Node.js + Express API, JWT + Passport, RBAC, BullMQ, Swagger) ->
  Data (PostgreSQL authoritative + Redis cache + MinIO/S3 file storage).
- Selected architecture = Alternative 1 (Centralized Identity via Home Affairs) +
  Alternative 4 (Federated Inter-Ministry System) + Alternative 3 features
  (appointments/queue/notifications) + Alternative 2 as assisted-access channel.
- General flow that MUST work after sync:
  1. Citizen requests service + authenticates (ID + OTP / alternative auth).
  2. Ministry identifies required info.
  3. Ministry sends authorized identity request to Home Affairs.
  4. Home Affairs verifies and returns ONLY permitted fields (DepartmentFieldScope).
  5. Ministry processes application with its own rules/records.
  6. Citizen gets status updates/notifications/receipts.
  7. System logs audit entries for every sensitive access.
- Functional requirements to satisfy: secure citizen profile, citizen auth (OTP + alternatives),
  digital document submission, authorized data retrieval, departmental data restriction,
  online application, progress tracking, appointment/queue, staff review/decisions,
  notifications (SMS/email/in-app), digital receipts, record maintenance + audit logging.
- Non-functional: ~3s response, TLS encryption, 99% uptime, mobile/low-bandwidth,
  privacy/data-minimization, RBAC + immutable audit, EN + Sesotho (i18next), WCAG
  accessibility (clear language, contrast, colour-independent actions, clear errors,
  responsive, elderly/disabled support).

8. API MAPPING CHEAT SHEET (FRONTEND ACTION -> BACKEND CALL)
--------------------------------------------------------------------------------
Login citizen: POST /auth/otp/request {nationalId} -> {masked?, devOtp} ;
  POST /auth/otp/verify {nationalId, code} -> {token, user:{id,role}}.
Login staff: POST /auth/staff/login {email,password} -> {token, user:{role,departmentCode}}.
Logout: POST /auth/logout (Authorization: Bearer <JWT>).
Me: GET /me -> profile; PATCH /me {email,preferredLanguage}.
Citizens (officer): POST /citizens {fullName,dateOfBirth,gender,citizenship,...} ;
  PATCH /citizens/:nationalId {fullName,address,phone}.
Catalogue: GET /services?dept=&q= ; GET /departments.
Apply: POST /documents (multipart file+type) -> {fileId/documentId} ;
  POST /applications {serviceCode,formData,documentIds} -> {id,reference,status,missingDocuments}.
Track: GET /applications ; GET /applications/:id ; POST /applications/:id/respond {formData} ;
  POST /applications/:id/withdraw ; POST /applications/:id/pay {paymentMethod}.
Verify (staff): POST /identity/verify {applicationId} (dept staff) or {nationalId} (HA officer)
  -> {citizen:{filtered fields}, cache: hit|miss}.
Staff queue: GET /applications (auto dept-scoped) ; POST /applications/:id/assign {assign:true} ;
  PATCH /applications/:id/status {status,note} ; POST /applications/:id/documents/:doc/review.
Docs: GET /documents ; GET /documents/:id/download (blob) ; DELETE /documents/:id.
Appointments: GET /appointments/slots?departmentCode&date=YYYY-MM-DD ; POST /appointments
  {departmentCode,serviceCode?,startsAt} ; GET /appointments ; POST /appointments/:id/cancel|check-in|complete|no-show ;
  GET /appointments/:id/queue-position ; GET /queue?date ; POST /queue/call-next.
Notifications: GET /notifications ; PATCH /notifications/read-all ; PATCH /notifications/:id/read.
Receipts/payments: GET /receipts ; GET /receipts/:id ; GET /receipts/verify/:receiptNumber ; GET /payments.
Admin: GET/POST /admin/users ; PATCH /admin/users/:id ; POST /admin/departments ;
  GET/PUT /admin/departments/:code/scopes ; POST/PATCH /admin/services ; GET /audit-logs?action&actorId&limit&offset.
All authenticated calls: Header Authorization: Bearer <JWT>. Handle 401 (re-login),
  403 (wrong role/dept), 404 (other dept's app), 409 (conflict/terminal), 413 (file), 429 (rate/OTP), 402 (pay fail).

9. DATABASE QUERY REQUIREMENTS (AGENT MUST ENSURE)
--------------------------------------------------------------------------------
- Use Prisma only (no raw SQL except advisory locks already in code). All PKs BigInt -> serialize as String.
- Every write that touches >1 table MUST be in prisma.$transaction (pay, status change, doc review,
  respond, withdraw, book, checkIn, callNext, createStaff, setScopes). No partial saves.
- Ownership checks in EVERY query: citizenId===token.id for citizen reads/writes/documentIds;
  departmentId===token.departmentCode for staff lists/views/downloads; admin bypass only for list/audit.
- Identity verify: lookup DepartmentFieldScope for dept, select ONLY those columns from Citizen,
  check Redis identity:{nationalId} first (TTL 300s), on miss query DB then setJSON, on citizen/scope
  update DEL key. Write IdentityRequest row + AuditLog (field names only).
- Appointments: advisory lock hashtext(slot:{dept}:{iso}) for capacity (max 2/slot) + 1-per-dept-per-day
  clash check; queue lock hashtext(queue:{dept}:{date}) for queueNumber max+1. Invalidate slots cache.
- AuditLog: append-only (create only, no update/delete endpoint). Include actorId/role/dept/action/
  resourceType/resourceId/details(non-PII)/ip. ACCESS_DENIED on every 403.
- Seed + migrations must run clean on fresh docker postgres. Never edit migrated data manually.
- Add indexes where frontend filters (status, departmentId, citizenId, reference, startsAt).
